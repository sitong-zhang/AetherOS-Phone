# AetherOS 安全设计基线

本文件定义 AetherOS 的安全规格与验收口径，覆盖隐私与安全、L1 安全域、移植原则与硬件接口层。
代码实现位于 `secure/`，整体架构见
[`ARCHITECTURE.md`](ARCHITECTURE.md)，产品定位见 [`SYSTEM-BLUEPRINT.md`](SYSTEM-BLUEPRINT.md)。

## 0. 定位

AetherOS 是基于 Linux 内核、用户态完全自研、主打安全的手机操作系统，目标设备为开发板与
谷歌 Pixel 系列真机。当前在云计算机上进行系统构建与调试，软件模拟是开发手段。

> 口号：长明 Aether · 机可失，密不失（副：灯不灭，密不泄）

安全目标：设备遗失、被夺、被胁迫、被插线拆解时，数据仍受保护。

## 1. 威胁模型

| 攻击者 | 能力 | 防护档 |
| --- | --- | --- |
| 捡到 / 偷到设备的人 | 猜解锁屏口令、连续试错 | 常规档：输错达阈值抹除用户数据 |
| 胁迫机主的人 | 逼问口令、要求当面解锁 | 胁迫档：诱饵环境、真实卷不挂载 |
| 有电脑的取证者 | USB 数据强插、ADB、刷机、读盘 | 熔断档：确认攻击意图即连系统抹除 |
| 有工具的拆解者 | 拆机、短接测试点、物理提取 | 熔断档：防拆触点 / 短接取核心数据 → 报警 + 抹除系统 |
| 离线爆破者 | 拿到磁盘镜像离线穷举 | 高强度口令 + 设备密钥绑定 + 零存储验证锚 |
| 篡改者 | 改审计链、改计数、改系统分区 | 设备密钥 HMAC 审计链 + 完整性自检 |

## 2. 三档数据保护

| 档 | 触发 | 抹除范围 | 后果 |
| --- | --- | --- | --- |
| 常规 | 锁屏口令输错达 `max_fails` | `data/` 用户数据 | `sys/` 系统本体逐字节保留，可再登录 |
| 胁迫 | 输入胁迫口令 | 真实卷不挂载 | 进入诱饵环境、静默留痕 |
| 熔断 | 安全锁定态下 L3 确认攻击意图 | `data/ + sys/ + journal/ + receipt/ + lockdown/` 全部 | 软件熔断：系统不可恢复，刷机可重装；并下发硬件熔断指令 |

常规档由 `ae_secure_wipe()` 保证 `sys/` 逐字节不变；熔断档由 `ae_ld_brick()` 连 `sys/` 一并
抹除。两者共用隔离存储后端，语义严格分离。

### 2.1 攻击意图判定层

物理信号只作为证据，是否触发熔断由**攻击意图判定层**（`secure/core/aether_intent.c`）依据
结构化观测推导。判定层为纯函数，相同观测恒得相同判决，无隐藏状态、无累计阈值。

输入观测（检测层可直接给出的客观量）：

| 字段 | 取值 |
| --- | --- |
| USB 枚举类别 | 无 / 仅充电 / HID / 已鉴权 MTP / 大容量存储 / ADB / fastboot / 未知探针 |
| 行为动词 | 无 / 鉴权成功 / 鉴权失败 / 枚举查询 / 读公开区 / 读核心区 / 导出核心区 / 写引导区 / 触碰密钥区 / 反复爆破 / 全盘抓取 |
| 访问区域 | 无 / 公开区 / 用户数据区 / 系统核心区 / 密钥区 |
| 会话状态 | 鉴权是否通过、连续鉴权失败次数、批量读取字节数 |
| 物理信号 | 机壳开启、测试点短接、有效签名维修凭证 |

输出为判据等级、归一化事件、命中规则编号与可审计理由。判定顺序与规则：

| 级别 | 判据 | 归一化事件 | 动作 | 删除 |
| --- | --- | --- | --- | --- |
| L3 确认攻击 | 核心资产区出现导出 / 写引导 / 爆破行为；密钥区触碰；拆机短接触及核心区；未鉴权调试接口执行导出或刷写 | `core-export` / `key-tamper` / `short-core` / `usb-data` | 软件熔断 + 硬件熔断指令 + 报警 + 变砖标记 | 连系统抹除 |
| SERVICE 维修 | 有效签名维修凭证，且未触及 L3 特征 | `service-mode` | 启用维修白名单 | 无 |
| L2 可疑 | 核心区侦察读、未授权调试接口枚举、鉴权失败、非白名单存储枚举 | `core-read` / `adb-unauthorized` / `auth-fail` / `mass-enum` | 断连 + 记录取证 + 进入 SUSPECT | 零删除 |
| L1 无害 | 仅充电、常规已鉴权传输、维修开盖、维修短接未触核心区 | `usb-charge` / `chassis-open` / `testpoint-short` | 记录取证 + 轻报警 | 零删除 |
| 兜底 | 观测不足以判定 | `usb-charge` | 按无害处理（fail-safe） | 零删除 |

升级到 L3 的条件：观测中同时出现「触及核心资产」与「破解 / 导出 / 取核心数据」行为特征。
仅插入一根 USB 线、仅枚举调试接口而无后续行为，最高判 L2，绝不触发熔断。

**证据链口径**：`evidence.log` 与 `ae_hal_evidence_count()` 只用于取证、审计与外部可观测查询，
不设自动升级阈值，不参与触发判定。从 L1/L2 升级到 L3 必须由判定层对新观测重新判定，不由历史
事件累计触发。该设计保证正常维修过程中的多次插拔、开盖与短接不会累积成毁机动作。

官方维修白名单豁免物理开盖与短接，但不豁免 L3 核心区导出，防止伪造凭证绕过。

### 2.2 软件熔断与硬件熔断

| | 软件熔断 | 硬件熔断 |
| --- | --- | --- |
| 实现 | 抹除全部分区 + `BRICKED` 标记 + 引导级拦截 | 真机 eFuse/OTP 一次性烧写，或 crowbar 烧毁存储供电 |
| 后果 | 系统本体不可恢复，刷机可重装 | 物理永久变砖 |
| 当前状态 | 已实现（调试环境对存储区真实抹除） | 调试环境仅仿真指令锁存，真机阶段由硬件后端执行 |
| 外部可观测 | `ae_ld_state() == BRICKED` | `ae_hal_hw_fuse_backend()` 返回 `simulated(...)` |

软件熔断不称为「永久变砖」。硬件熔断在云计算机上为仿真熔断指令锁存，真机阶段由
eFuse/OTP/crowbar 物理执行。

## 4. 安全功能规格

### 4.1 数据保护与密钥

- 输错口令达阈值即销毁保险库，产出离线可验的销毁证明。
- 胁迫口令进入诱饵环境，真实卷不挂载。
- 一键熔断 Panic、防篡改审计链、系统完整性自检（篡改即擦）。
- TEE 密钥锚点：软件后端用于调试环境，真机后端对接安全芯片与 eFuse。
- 设备自证 Attestation：以设备密钥对安全状态签名，输出可离线验证的报告。
- 会话空闲锁定、暴力破解指数退避、内存密钥锁定与清零。

### 4.2 安全锁定模式（Lockdown Mode）

**首启硬门**：开机引导序列中的专用安全密码设定步骤不可跳过，未设定不进入系统。
`ae_ld_oobe_gate()` 在未设定或已软件熔断时返回拦截。硬门挂在系统服务编排之前，
配合验证启动防止通过 recovery 或刷写 system 分区绕过。

**专用安全密码规格**

| 项 | 规格 |
| --- | --- |
| 长度 | 20–30 位 |
| 字符类 | 必含大写、小写、特殊符号 |
| 连续序列 | 递增 / 递减连续序列长度 ≤ 5（12345 允许、123456 拒绝） |
| 性质 | 不可重置、不可找回、无修改入口，仅首次设定有效 |
| 确认交互 | 二次确认窗提示物理抄录 + 明文再回显一遍 + 确定按钮 10 秒冷却 |
| 存储 | 系统零存储密码明文：密码即 wrapping key，仅落盘 `verifier = HMAC(device_key, PBKDF2(pw, salt))`，单向派生、无法倒推；明文不落盘、不进日志与快照，用完即从内存清零 |

零存储的工程含义：判断口令对错必须保留一个由口令参与、无法倒推回口令的验证锚；若连锚都不留，
机主自身也无法解锁。真机将 `device_key` 放入 TEE/eFuse 后，离线穷举该锚不可行。

**进入安全锁定模式**

1. 电源键 + 音量下同时按住满 10 秒：不足 10 秒无效；超时保持待确认，不自动进入。
2. 满 10 秒后再按一下音量上，进入安全锁定模式。
3. 未设定专用安全密码时，组合键完全无效（防误触、防他人乱按导致变砖）。

**锁定态行为**

- 唯一解锁方式为专用安全密码；锁屏、生物识别、ADB、recovery、刷机、USB、调试口全部封死。
- 正常充电、维修开盖、维修短接未触核心区：只记录取证、零删除，保持锁定。
- 未授权 ADB、反复鉴权失败、核心区侦察：断连取证、进入 SUSPECT、零删除。
- 触及用户数据 / 系统核心区且判定为攻击意图：立即软件熔断 + 硬件熔断指令 + 报警 + 变砖标记。
- 官方维修白名单下物理开盖与短接不触发熔断；L3 核心区导出不豁免。
- 忘记密码无法退出安全锁定，无找回、无后门、无救援口令；软件熔断状态跨重启持久。

### 4.3 物理安全接口层

`aether_phys_hal` 把 USB 数据接入、机壳开合、测试点短接、组合键、蜂鸣器报警、安全芯片、
单调时钟与硬件熔断抽象为可替换接口，上层状态机只依赖接口，不依赖 GPIO 或寄存器。

- 调试环境：`AE_HAL_SIM` 后端，结构化观测注入、可注入确定性时钟、证据链 `evidence.log`。
- 真机：`AE_HAL_HW` 后端，GPIO + 安全芯片 + eFuse/OTP/crowbar 物理执行，上层零改动。
- `ae_hal_hw_fuse_burn()` 在调试环境仅仿真熔断指令锁存；`AE_HAL_HW` 后端当前为占位，
  `open` 如实返回失败，不伪造硬件能力。

## 5. 逐条验收口径

| 能力 | 验收方式 | 自测组 |
| --- | --- | --- |
| 密码强度 | 20/30 边界、各类字符缺失、连续序列 5/6 边界各一用例 | L1 |
| 首启硬门 | 未设定时 `oobe_gate=0` 且组合键无效 | L2 |
| 10 秒冷却 | 小于 10000ms 拒绝、大于等于 10000ms 通过、未满不落锚 | L2 |
| 零存储 | 全盘扫描运行根，密码明文 0 命中；验证锚存在 | L2 + CLI |
| 不可重置 | 二次 `provision_begin` 拒绝 | L2 |
| 组合键 | 不足 10 秒 / 松开 / 超时不进入；满 10 秒 + 音量上才进入 | L3 |
| 仅密码可解 | 错误密码无旁路、正确密码退出、状态跨重启持久 | L3 |
| L3 攻击意图熔断 | USB 破解 / 核心区导出 / 密钥触碰 / 短接取核心 → 软件抹除 + 硬件熔断指令 | L4 |
| 无害零删除 | 充电 / 开盖 / 维修短接 → 状态仍 LOCKED、`sys/` 零删除 | M |
| L2 取证 | 未授权 ADB → 进入 SUSPECT、零删除、不触发硬件熔断 | M |
| 核心区访问才熔断 | SUSPECT 下核心区导出（L3）才连系统抹除 | M |
| 维修白名单 | 开盖 / 短接 / ADB 全程不熔断；不豁免 L3 核心区导出 | M |
| 软件熔断口径 | 跨重启不可恢复，标注「刷机可重装」 | M |
| 仿真标注 | 真机硬件后端未实现、硬件熔断 simulation-only | M |
| 意图判定误判率 | 21 例观测样本（8 攻击 / 13 非攻击），误判 0 例 | N |
| 判定一致性 | 判据等级与归一化事件等级一致；纯函数确定性 | N |
| 判定层端到端 | 仅插线不熔断；同一根线导出核心区才熔断 | N |
| 变砖终态 | 任何密码与事件都退不出、开机硬门拦截、`sys/` 保持空 | L4 + CLI 引导级拦截 |
| 三档分离 | NORMAL 态物理事件不误触发熔断 | L5 |
| 密码学 | OpenSSL 3.x 独立复算标准向量 | 4/4 交叉验证 |

**当前自测：`bash scripts/secure.sh test` → 356 PASS / 0 FAIL + OpenSSL 交叉验证 4/4。**

## 6. 工程边界

1. 已实现能力位于 `secure/` 用户态安全整机，以本机 CLI 形式运行；随 Linux 手机 OS 启动的
   服务化集成待完成。
2. 物理事件检测在开发环境中为结构化观测注入；真机阶段由检测层输出同样结构，判定逻辑不依赖
   具体实现层。硬件熔断在开发环境中为仿真指令锁存。
3. H1–H4 属 Linux 内核与引导层，处于规划阶段。
4. 熔断删除的是存储区中的文件；真机变砖由 bootloader 与安全芯片管控，调试环境以「抹除系统区
   文件 + 落 `BRICKED` 墓碑 + 引导级拦截」仿真。
5. 二次确认窗在调试环境以文本与可注入时钟呈现；GUI 弹窗与 10 秒冷却按钮属交互层，
   待桌面接入。

## 7. 复现

```bash
bash scripts/secure.sh build          # -Werror 编译
bash scripts/secure.sh test           # 356 PASS / 0 FAIL + OpenSSL 4/4

# CLI 端到端（独立运行根，确定性时钟）
BIN=build/bin/aether-os; R=/tmp/aether-observe; PW='Abc!Def@Ghi#Jkl$Mn0PqRs'; rm -rf "$R"
$BIN --root "$R" --no-delay --ld-now 1000  ld-provision --pw "$PW" --now 11000
$BIN --root "$R" --no-delay --ld-now 40000 ld-gesture --now 40000
$BIN --root "$R" --no-delay ld-observe usb=fastboot                          # L2 可疑，零删除
$BIN --root "$R" --no-delay ld-observe short=1 chassis=1                    # L1 无害，零删除
$BIN --root "$R" --no-delay ld-observe service=1 chassis=1                  # SERVICE 白名单
$BIN --root "$R" --no-delay ld-observe usb=fastboot verb=export-core region=sys-core  # L3 熔断
grep -rlF "$PW" "$R" || echo "零存储：运行根内无密码明文"
```
