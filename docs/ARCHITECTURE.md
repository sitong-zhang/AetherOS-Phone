# AetherOS 架构

本文件定义目标架构、分层约束、验证轨道、硬件接口层、静态机检、阶段门禁与真机路线。
能力状态按证据标注：已实现、部分实现、规划中。

## 一、交付形态

AetherOS 是在云计算机上以软件模拟运行的完整移动操作系统整机：真实开机、真实出图、真实响应
输入。系统以完整 OS 形态交付，不以 Android 应用、安装包或预览壳的形式提供。

内核采用 Linux（ARM64 6.6.70），用户态（init、系统服务、合成器、框架、界面）完全自研，
不基于 AOSP，不基于现成发行版。目标设备为开发板与谷歌 Pixel 系列真机；当前在云计算机上
完成构建与调试，QEMU 软件模拟是验证手段。硬件相关能力通过可替换接口层定义，真机移植阶段
接入具体驱动，上层代码保持同源。

对既有应用格式的兼容由系统内独立子系统以容器化方式提供（可基于 AOSP / LineageOS /
Waydroid 等开源实现），与主系统自研不冲突。

## 二、双轨验证

云计算机无硬件虚拟化支持，整机验证使用 QEMU TCG 软件模拟。TCG 下 ARM64 整机启动按分钟计、
交互帧率不足 1fps，不适合作为交互体验的验收依据；反过来只用原生运行上层也无法证明内核能够
启动。因此拆成两条轨道：

| | A 轨 · 整机链路 | B 轨 · 交互与像素 |
| --- | --- | --- |
| 载体 | QEMU ARM64 + TCG，Linux 内核 + 自建根文件系统 | 同一份上层源码原生构建，接口层接仿真实现 |
| 证明 | 引导 → 内核 → init → 服务 → 合成器首帧 → 注入输入改变画面 | 交互延迟、动画帧率、布局、对比度/遮挡/裁切、状态机、长稳 |
| 不证明 | 帧率、动效手感、长稳、并发 | 内核启动、真实驱动 |
| 证据 | 冷启动到首帧耗时、连续帧变化、输入引起的可验证画面变化 | 像素与交互机器断言 |

**代码同源**：两轨使用同一份上层源码，差异仅在构建目标与接口实现选择。若为某一轨修改上层
调用方式或加入条件编译，判接口层不合格。每次改动两轨各出一份证据，缺一不计入已修。

## 三、分层

| 层 | 名称 | 职责 | 仓库落点 | 状态 |
| --- | --- | --- | --- | --- |
| L0 | 引导与固件 | 启动环境、镜像加载、校验、分区、失败回滚 | `boot/` | 部分实现 |
| L1 | 内核 | 调度、内存、IPC、文件系统、网络、驱动框架、电源、安全、调试 | Linux 6.6.70（`boot/` 构建链路） | 部分实现 |
| L2 | 接口层 HAL | 屏蔽硬件差异，向上提供统一能力接口 | `l2/` | 部分实现 |
| L3 | 系统服务 | init、包管理、通知、媒体、音频、相机、位置、电话、网络、时间、更新、日志、电源 | `guest/src/aether-init.c`、`aetherosd.c` 等 | 部分实现 |
| L4 | 图形与合成 | 显示管线、合成器、图层、帧调度、渲染原语、文字、图标、材质、转场 | `guest/src/aether-compositor.c`、`aether-render.c`、`aether-material.c` 等 | 部分实现 |
| L5 | 框架与运行时 | 服务发现、应用生命周期、窗口、输入分发、资源、权限、运行时 | `guest/src/` 业务层 | 部分实现 |
| L6 | 界面系统 | 设计语言、组件库、系统界面、系统应用 | `guest/src/aether-phone.c`、`aether-ui.c` 等 | 部分实现 |
| L7 | 生态与工程 | 商店、签名、沙箱、兼容层、工具链、构建、测试、文档 | `tools/`、`scripts/`、`docs/` | 部分实现 |

### 分层约束

1. 跨层只能通过显式接口；禁止跨层直调内部函数。
2. 硬件访问只发生在 L2 及以下；L3 以上不许出现设备节点路径、寄存器地址、厂商私有调用。
3. 上层不感知当前是调试环境还是真机，只感知接口能力。
4. 每层有独立可运行的测试入口。
5. 第 2 条必须机器可检，不靠自觉。

> 现状差异：`guest/src/` 中仍有若干 C 文件直接打开设备节点或读取内核接口（显示后端、
> 合成器、系统指标、兼容桥等）。按机检第 1 门属于不合格，是接口层阶段必须整改的项。
> 机检脚本如实报出命中，不因「能跑」而豁免。

## 四、L2 硬件接口层

```
上层（服务 / 框架 / 界面）
        ↓ 调用统一接口（能力查询 + 错误码 + 流控 + 状态）
接口层（定义能力，不含实现）         ← l2/include/
        ↓ 按配置选择
仿真实现（调试环境）  或  真机驱动（S6） ← l2/sim/
```

**十五个域**：显示、输入（触摸/按键）、音频、相机、Wi-Fi、蓝牙、蜂窝/基带、定位、传感器、
生物识别、电源与电池、热管理、存储、网络（通用）、时钟/RTC。每个域接口必须提供
**能力查询 + 错误码 + 流控计数**三件套；调试环境给出仿真实现（内存帧缓冲、脚本注入、
虚拟音频/网络、完整基带状态机等）；真机阶段按实现层替换，未接入的域标注「仅仿真」并说明原因。

**流控与背压**：帧提交、输入事件、音频、相机、网络、日志、存储、基带、电源、传感器都必须有
明确的排队/丢弃/阻塞策略、上限、计数与查询入口。关键边界事件（按下/抬起、注册失败、掉电、
状态跳变）不得丢弃；降频必须上报，不静默降级。

**接口自证**：不启动整机界面，直接对每个接口做高频、超时、断开、异常返回、并发调用测试；
支持仿真/桩/真机实现切换；可主动注入失败、延迟、断连；缺实现或实现报错时系统明确提示并
降级运行，不白屏、不死机、不静默失败。

## 五、静态机检

| 门禁 | 检查方式 | 不通过判据 |
| --- | --- | --- |
| 无设备路径上浮 | 扫 L3 以上源码，禁止设备节点与内核接口直连 | 命中即失败 |
| 无跨层直调 | 文件头部声明的依赖之外出现 include / 符号引用 | 命中即失败 |
| 接口覆盖 | 每域必须有「能力查询 + 错误码 + 流控计数」三件套符号 | 缺项即失败 |
| 实现可替换 | 编译两次（仿真/桩实现），上层目标文件哈希一致 | 不一致即失败 |
| 单一参数源 | 业务代码出现裸数值字号/间距/时长/尺寸 | 命中即失败 |

门禁由 `scripts/aether.sh test` 统一调用。**验收标准、门禁脚本、断言阈值不由实现方修改**；
变更须附理由与证据。

## 六、阶段与门禁

| 阶段 | 目标 | 结束标志 |
| --- | --- | --- |
| S1 环境打通 | 一键起停重建，A 轨到首帧 | 连续三次重建一致；首帧后连续帧变化可证 |
| S2 接口层成型 | 十五域抽象 + 仿真实现 | 接口自测全绿；切换实现不改上层；静态机检全过 |
| S3 整机闭环 | 引导到桌面全通 + 输入可用 | 全流程自动跑通；软键盘可用（含中文），一票否决 |
| S4 能力补齐 | 模块清单补齐 | 清单无缺项，逐模块可交互且过像素断言 |
| S5 稳定与性能 | 长稳、性能、异常恢复 | 长稳通过；六类异常可自动发现；性能可对比 |
| S6 真机移植 | 换实现层上真机 / 树莓派 | 上层零改动；可刷可回滚 |

门不过不进下一阶段；仿真通过不等于真机通过，两条证据分开记录。

## 七、参数治理

- 唯一参数源：`guest/src/aether-tokens.h`（布局令牌 `TK_*`）与
  `guest/src/aether-glass-spec.h`（光学常量）。业务代码不出现裸数值。
- 每个参数注明设备、分辨率与取值依据。
- 改参数必须附前后帧/帧时对比，随提交归档。
- 需求只描述效果，数值只出现在参数源与实测报告中。

## 八、启动链（A 轨）

```
QEMU aarch64 (-M virt, TCG)
   → Linux 6.6.70 Image 引导
   → 挂载自建 ext4 根文件系统
   → 自研 PID 1 aether-init
   → 服务编排（aetherosd / compositor / watchdog / bootdiag / selftest）
   → virtio-gpu 输出首帧
   → 注入输入改变画面
   → 逐帧取证 + 开机门禁机检
```

内核与根文件系统从源码构建，或提供带校验和的获取脚本；构建脚本不依赖机器绝对路径或系统
目录写权限。链路细节与一键用法见 [`../boot/README.md`](../boot/README.md)。

## 九、真机路线

云端 S1–S5 全部通过、上层代码稳定后进入真机阶段。选型硬条件是主线 Linux 已有该机端口
（内核 defconfig + dtb + 显示/触摸可用），而非「能解锁」；官方工厂镜像只用于回滚到安卓。
真机阶段只允许替换接口实现层，不修改界面、服务、框架的调用方式。副目标为树莓派，
证明「换硬件只换实现」。

## 十、安全子系统

安全是系统核心设计目标。`secure/` 是一套独立编译运行的用户态安全整机，与 L0–L7 分层正交，
不依赖图形栈：

```
aether-os（整机入口 / 交互 shell）
  ├─ 认证引擎 ─ 口令哈希 / 失败计数（原子落盘 + HMAC + 审计链交叉核对）/ 退避 / 空闲锁定
  ├─ 加密保险库 ─ DEK（随机，仅内存）← KEK（口令派生）密封；数据卷 ChaCha20+HMAC 静态加密
  ├─ 销毁引擎 ─ crypto-shred + 多轮覆写 + 系统区摘要硬断言 + 销毁证明
  ├─ 攻击意图判定层 ─ 结构化观测 → 判据等级 → 归一化事件 → 状态机
  ├─ 审计链 ─ 设备密钥 HMAC 链式记录，防篡改
  ├─ 完整性 ─ 基线锚定，篡改即擦
  └─ 隔离存储 ─ sys/（系统）| data/（用户数据）| journal/（日志）| receipt/（证明）| lockdown/（锁定）
```

**不变式**：常规销毁作用域严格限于 `data/`；擦除前后 `sys/` 摘要必须逐字节一致。熔断档
（L3 确认攻击意图）才连 `sys/` 一并抹除，两者共用同一存储后端、语义严格分离。

规格、威胁模型与逐条验收见 [`SECURITY-BASELINE.md`](SECURITY-BASELINE.md)。

> 工程边界：当前为云计算机上以本机 CLI 形式运行的用户态安全整机，随 Linux 手机 OS 启动的
> 服务化集成待完成；真机阶段需以 TEE / 安全芯片锚定失败计数、以块设备安全擦除替代文件级覆写，
> 并接入物理检测层与硬件熔断后端。
