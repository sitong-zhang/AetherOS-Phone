# AetherOS 系统蓝图

本文件定义 AetherOS 的产品定位、整体思路、分层架构、验证轨道、安全主线、目录职责、阶段状态与
工程边界，是架构与实现决策的单一真相源，也是产品规格与验收口径的基准。

## 0. 定位

**AetherOS = 基于 Linux 内核、用户态完全自研、主打安全的手机操作系统。**

- 内核采用 Linux（ARM64 6.6.70），用户态（init、系统服务、合成器、框架、界面）自研，
  不基于 AOSP，不基于现成发行版。
- 以完整 OS 形态交付，不以 Android 应用、安装包或预览壳的形式提供。
- 目标设备为开发板与谷歌 Pixel 系列真机；当前在云计算机上进行系统构建与调试，
  QEMU 软件模拟是开发手段而非产品形态。
- 安全是核心设计目标：设备遗失、被夺、被胁迫、被插线拆解时，数据仍受保护。

> 口号：长明 Aether · 机可失，密不失（副：灯不灭，密不泄）

## 1. 整体思路

同一份自研上层源码在两个环境中使用：云计算机上的构建调试环境，与真机环境。两者的差异仅在
构建目标与硬件接口层的实现选择，上层代码保持同源，不以条件编译分叉。

```
        同一份自研用户态源码（guest/ 等，代码同源）
                          │
        ┌─────────────────┼─────────────────┐
        │  云计算机调试环境                 │  真机环境
        │  Linux 6.6.70 内核 (ARM64)       │  换 L2 实现层：
        │  + 自建 ext4 根文件系统          │  GPIO / TEE / eFuse / 真驱动
        │  + QEMU TCG 软件模拟            │  刷开发板 + 谷歌 Pixel
        │  A 轨证「能开机」/ B 轨证「能交互」│  上层零改动
        └─────────────────┬─────────────────┘
                          │
              硬件能力统一走「L2 十五域 HAL 可替换接口」
              调试环境 = 仿真实现；真机 = 真实驱动
```

构建顺序：在调试环境中把「引导 → Linux 内核 → 挂载根文件系统 → init 服务编排 → 图形首帧 →
锁屏/解锁/桌面 → 输入/网络/权限安全」逐环跑通并留存证据（A 轨），以同一份上层源码原生运行
验证交互、动效、像素与长稳（B 轨）；链路通过后，仅替换硬件接口层实现，将上层移植到真机。

`secure/` 用户态安全整机当前以本机 CLI 形式独立运行与验证，后续接入 L3 系统服务层，
随 Linux 手机 OS 启动。

## 2. 分层架构

| 层 | 名称 | 职责 | 仓库载体 | 状态 |
| --- | --- | --- | --- | --- |
| L1 | 内核 | 调度 / 内存 / IPC / 文件系统 / 网络 / 驱动 / 电源 / 安全 / 调试 | Linux 6.6.70（`boot/` 构建链路） | 部分实现 |
| L2 | 接口层 HAL | 屏蔽硬件差异，十五域统一能力接口 | `l2/`（接口 + 仿真 + 桩 + 自测） | 部分实现 |
| L3 | 系统服务 | init 编排 / 包管理 / 账户 / 通知 / 媒体 / 网络 / 更新 / 日志 | `guest/` 上层 + `secure/` 待接入 | 部分实现 |
| L4 | 框架 | 窗口 / 控件 / 输入 / 动效 / 权限 API | `guest/` | 部分实现 |
| L5 | 应用 | 桌面 / 锁屏 / 设置 / 系统应用 | `guest/` | 部分实现 |
| L6 | 视觉 | 液态玻璃设计系统、参数单一源 | `guest/src/aether-tokens.h` | 部分实现 |
| L7 | 兼容层 | 独立子系统容器化运行第三方应用 | `guest/third_party/`（AVF / Waydroid 调研） | 部分实现 |
| L8 | 构建与验收 | 六种一键、门禁、证据 | `scripts/` `tools/` | 部分实现 |

硬件访问只在 L2 及以下发生；L3 以上源码禁止直连设备节点与内核接口，由静态机检扫描判定。
设计参数集中在单一真相源，门禁规则固定，不由实现方修改。

## 3. 双轨验证

| 轨道 | 载体 | 证明范围 | 不证明 |
| --- | --- | --- | --- |
| A 轨 · 整机链路 | QEMU TCG 软件模拟，Linux 内核 + 自建根文件系统 | 「引导 → 内核 → 挂载根 → 服务 → 首帧 → 输入生效」链路通 | 帧率 / 动效 / 长稳（TCG 属软件模拟） |
| B 轨 · 交互与像素 | 同一份上层源码原生运行 + 仿真接口 | 交互延迟 / 动效 / 布局 / 对比度 / 状态机 / 长稳 | 内核启动、真实驱动 |

两轨必须使用同一份上层源码。若为某一轨修改上层调用方式或加入条件编译，判接口层不合格。

## 4. 安全主线

安全目标：设备遗失、被夺、被胁迫、被插线拆解时，数据仍受保护。

### 4.1 三档数据保护

| 档 | 触发 | 抹除范围 | 后果 |
| --- | --- | --- | --- |
| 常规 | 锁屏口令输错达阈值 | `data/` 用户数据 | `sys/` 系统本体保留，可再登录 |
| 胁迫 | 输入胁迫口令 | 真实卷不挂载 | 进入诱饵环境、静默留痕 |
| 熔断 | 安全锁定态下 L3 确认攻击意图 | 全部区（含 `sys/`） | 软件熔断，系统不可恢复（见 4.2） |

### 4.2 攻击意图分级与熔断

物理信号本身只作为证据，是否触发熔断由**攻击意图判定层**依据结构化观测推导。判定层以
USB 枚举类别、行为动词、访问区域、鉴权结果、维修凭证与物理信号为输入，输出判据等级、
归一化事件与可审计理由。信息不足时按最低等级处理，单一 USB 枚举不构成攻击意图。

| 级别 | 判据 | 动作 |
| --- | --- | --- |
| L1 无害 | 充电 / 开盖 / 维修短接未触核心区 / 正常数据连接 | 记录取证、零删除、保持锁定 |
| L2 可疑 | 未授权 ADB·fastboot / 反复鉴权失败 / 存储枚举 / 核心区侦察读 | 断连、记录取证、进入 SUSPECT、零删除 |
| L3 确认攻击 | USB 强插破解 / 短接触及核心区 / 核心区导出 / 密钥区触碰 | 软件熔断 + 硬件熔断指令 + 报警 |
| SERVICE | 有效签名维修凭证 | 豁免物理开盖与短接，不豁免 L3 核心区导出 |

证据链只作取证与审计，不设自动升级阈值；从 L1/L2 升级到 L3 必须由判定层对新观测重新判定，
不由历史事件累计触发。该设计使正常维修过程中的多次插拔、开盖与短接不会累积成毁机动作。

软件熔断与硬件熔断分开定义与验收：

- **软件熔断**：抹除全部数据分区与系统分区、写 `BRICKED` 标记、引导级拦截。系统不可恢复，
  刷机可重装。
- **硬件熔断**：真机 eFuse/OTP 一次性烧写或 crowbar 烧毁存储供电，物理永久变砖。
  调试环境仅提供仿真熔断指令锁存，真机阶段由硬件后端执行。

### 4.3 其他安全能力

输错即自毁保险库、离线可验销毁证明、胁迫口令与诱饵环境、一键熔断 Panic、设备自证
Attestation、TEE 密钥锚点（软件后端 / 真机硬件后端）、防篡改审计链 HMAC、防重启绕过计数、
首启强制设定零存储专用安全密码。隐私指示器、权限时间轴、防肩窥与验证启动链处于规划阶段。

规格、威胁模型与逐条验收见 [`SECURITY-BASELINE.md`](SECURITY-BASELINE.md)。

## 5. 目录职责

| 路径 | 职责 | 状态 |
| --- | --- | --- |
| `secure/` | 用户态安全整机：密码学、隔离存储、认证/保险库/销毁、审计链 HMAC、TEE 锚点、设备自证、攻击意图判定层、物理安全接口、安全锁定/熔断、CLI 与全套自测 | 已实现，356 项自测通过 + OpenSSL 4/4 |
| `guest/` | 自研用户态上层：init / 合成器 / 渲染 / 桌面 / 系统应用 + 兼容层调研 | 部分实现，按接口层解耦中 |
| `l2/` | 十五域 HAL：接口定义 + 仿真实现 + 桩 + 自测 | 部分实现 |
| `boot/` | 整机引导链路：Linux 内核配置 + 自建 ext4 根盘 + QEMU 启动 + 开机门禁 | 部分实现 |
| `scripts/` | 六种一键操作 + 安全整机一键脚本 | 部分实现 |
| `tools/` | 基线采集、静态机检、证据渲染 | 部分实现 |
| `docs/` | 产品规格与架构文档 | 见 §8 |

## 6. 阶段状态

| 阶段 | 目标 | 状态 |
| --- | --- | --- |
| S1 环境打通 | 一键起停重建、A 轨到首帧 | 部分实现：移动端根文件系统与图形首帧待取证 |
| S2 接口层成型 | 十五域抽象 + 仿真实现 + 静态机检全过 | 部分实现：上层历史直连待解耦 |
| S3 整机闭环 | 引导到桌面全通 + 软键盘（含中文）可用（一票否决硬门） | 规划中 |
| S4 能力补齐 | 全量模块清单无缺项、逐模块过像素断言 | 规划中 |
| S5 稳定与性能 | 长稳、异常自发现、性能可对比 | 规划中 |
| S6 真机移植 | 换 L2 实现层上开发板 / Pixel | 规划中（最终目标：刷真机实测） |

六种一键操作（构建 / 启动 / 关闭 / 重建 / 跑测 / 取证）统一入口为 `scripts/aether.sh`。
每轮改动保留状态断言、日志与哈希证据；门禁规则固定、命中即失败、不由实现方修改。

## 7. 工程边界

1. 完整 Linux 手机 OS 尚在建设中：根文件系统、图形桌面、软键盘与随系统启动的安全服务
   处于集成阶段，不标记为已达成。
2. `secure/` 的已实现能力以本机 CLI 形式运行，随 Linux 手机 OS 启动的服务化集成待完成。
3. 物理事件检测在开发环境中为结构化观测注入；真机阶段由检测层（USB 控制器枚举、协议解析、
   防拆触点）输出同样的观测结构。判定逻辑不依赖具体实现层。
4. 硬件熔断在开发环境中为仿真指令锁存，真机物理永久变砖依赖 TEE / 安全芯片 / eFuse。
5. 验证启动、故障隔离、地址隔离与内核硬化属 Linux 内核与引导层，处于规划阶段。
6. 兼容层未接入；软件模拟环境下的交互与像素结论不作为真机体验结论。

## 9. 复现

```bash
bash scripts/secure.sh build          # -Werror 编译，零告警
bash scripts/secure.sh test           # 356 PASS / 0 FAIL + OpenSSL 4/4
python3 tools/gate_l2.py              # 接口层静态机检
bash scripts/aether.sh test           # 上层自测 + 机检 + 基线采集
```

构建与验证不依赖特定手机、私有云接口或机器绝对路径，可在新的云计算机环境中复现。
