## 0. 一句话定位

**AetherOS = 基于 Linux 内核、用户态完全自研、主打安全的真手机操作系统。**

- 内核用 **Linux**（ARM64 6.6.70），**不自研内核**；用户态（init / 服务 / 合成器 / 框架 / 界面）完全自研，
  不基于 AOSP、不基于现成发行版。
- **是真 OS，不是 App / APK / 套壳 / 预览包**。最终**刷入开发板与谷歌 Pixel 真机实测**。
- 当前只在**云电脑**上做系统构建与调试，QEMU 软件模拟只是**开发手段**，不是产品形态。
- **主打安全**是核心卖点：手机丢了/被夺/被逼问/被插线拆解，也护住数据。

> **口号：长明 Aether · 机可失，密不失**（副：灯不灭，密不泄）

⚠️ **判向红线（历史上跑偏过两次，务必记住）**：
1. 产品内核是 **Linux**。`kernel/` 里的自研 x86_64 内核是**研究性 R&D 教学代码，非产品内核**，
   其 ring3「安全 demo」经审计有 V1–V17 缺陷，**不代表产品安全能力**，切勿拿来当产品内核吹。
2. **不做 APK 交付**。历史 `vm/` 宿主引擎已归档停用；APK/下载器/公网发布页都不是交付物。
3. 云电脑软件模拟 ≠ 真机。TCG 里做性能/体验验收永远过不了门，故有双轨（见 §3）。

## 1. 整体思路（"漏掉的那条线"，从调试到真机）

```
        同一份自研用户态源码（guest/ 等，代码同源，不许 #ifdef 分叉）
                          │
        ┌─────────────────┼─────────────────┐
        │  云电脑调试阶段（现在）            │  真机阶段（S6，将来）
        │  Linux 6.6.70 内核(ARM64)        │  换 L2 实现层：
        │  + 自建 ext4 根文件系统           │  GPIO/TEE/eFuse/真驱动
        │  + QEMU TCG 软件模拟             │  刷开发板 + 谷歌 Pixel
        │  A 轨证"能开机" / B 轨证"能交互"  │  上层零改动
        └─────────────────┬─────────────────┘
                          │
              硬件能力全部走「L2 十五域 HAL 可替换接口」
              云端 = 仿真实现；真机 = 真驱动（V2 §3.3 / §5）
```

**构建逻辑一句话**：先按 V2 在云电脑上把「引导→Linux 内核→挂根→init 服务→图形出图→
锁屏/解锁/桌面→输入/网络/权限安全」整条链路**逐环真实跑通并留证据**（A 轨），
用同一份上层源码原生跑「交互/动效/像素/长稳」（B 轨）；全部通过后**只换 L2 实现层**
把上层原样搬到真机刷入实测。任何一环断掉都不算跑通，任何阶段只写真实状态。

**安全能力（`secure/`）如何进产品**：目前是 x86_64 本机 CLI 的可独立验证安全整机，
下一阶段要**接成随 Linux 手机 OS 启动的服务**（L3 系统服务层），才随系统出货。

## 2. 八层架构（V2 §4.1）

| 层 | 名称 | 职责 | 本仓库载体 | 状态 |
|---|---|---|---|---|
| L1 | 内核 | 调度/内存/IPC/文件系统/网络/驱动/电源/安全/调试 | **Linux 6.6.70**（产品）；`kernel/` 自研 x86_64 为 **R&D 非产品** | 产品内核构建链路未入仓 |
| L2 | 接口层 HAL | 屏蔽硬件差异，十五域统一能力接口 | `l2/`（接口+仿真+桩+自测） | 部分实现（门1 有 guest/ 历史直连债） |
| L3 | 系统服务 | init 编排/包管理/账户/通知/媒体/网络/更新/日志… | `guest/` 上层 + `secure/` 待接入 | 部分实现 |
| L4 | 框架 | 窗口/控件/输入/动效/权限 API | `guest/` | 部分实现 |
| L5 | 应用 | 桌面/锁屏/设置/系统应用 | `guest/` | 部分实现 |
| L6 | 视觉 | 液态玻璃设计系统、参数单一源 | `guest/src/aether-tokens.h` | 部分实现 |
| L7 | 兼容层 | 独立子系统容器化运行第三方应用 | `guest/third_party/`（AVF/Waydroid 调研） | 部分实现/未接入 |
| L8 | 构建与验收 | 六种一键、门禁、证据四件套 | `scripts/` `tools/` `evidence/` | 部分实现 |

> 铁律：**硬件访问只在 L2 及以下**，L3 以上源码禁止 `/dev/`、`/sys/class/`、`/proc/` 直连
> （机检扫描），参数集中在单一真相源，门禁规则不由执行方修改。

## 3. 双轨（V2 §2.6）——为什么必须分开

| 轨道 | 载体 | 只证明 | 不证明 |
|---|---|---|---|
| **A 轨 · 整机链路** | QEMU TCG 软件模拟，Linux 内核 + 自建根盘 | 「引导→内核→挂根→服务→首帧→输入生效」**链路通** | 帧率/动效/长稳（TCG 慢约 30 倍） |
| **B 轨 · 交互与像素** | 同一份上层源码 x86_64 原生 + 仿真接口 | 交互延迟/动效/布局/对比度/状态机/长稳 | 内核启动、真实驱动 |

**必须是同一份上层源码**，差异只在构建目标与 L2 实现选择；若为 B 轨改上层（加 `#ifdef`）判接口层不合格。

## 4. 安全主线（招牌，为什么"主打安全"）

安全主线：**手机丢了 / 被夺 / 被逼问 / 被插线拆解，也护住数据。**

### 4.1 三档数据保护（严格区分）
| 档 | 触发 | 抹除范围 | 后果 |
|---|---|---|---|
| 常规 | 锁屏口令输错达阈值 | `data/` 用户数据 | `sys/` 系统本体保留，可再登录 |
| 胁迫 | 输胁迫口令 | 真实卷不挂载 | 进诱饵环境、静默留痕 |
| 熔断 | 安全锁定态下 **L3 确认攻击意图** | 全部区（连 `sys/`） | 系统本体不可恢复（见 4.2） |

### 4.2 熔断按「攻击意图分级」（用户 11-14 钦定 + 评估报告 §4.3，本阶段落地）
**事件只作证据，行为/攻击意图才触发**——不是「插 USB / 开盖 / 碰测试点就删」：

| 级别 | 判据（可机器判定） | 动作 |
|---|---|---|
| L1 无害 | 充电/开盖/维修短接未触核心区/正常数据连接 | 记录取证、零删除、保持锁定 |
| L2 可疑 | 未授权 ADB·fastboot/反复鉴权失败/存储枚举/核心区侦察读 | 断连+取证累计、进 SUSPECT、零删除 |
| L3 确认攻击 | USB 强插破解/短接触及核心区/核心区导出/密钥区触碰 | **立即摧毁系统 + 烧毁硬件** |
| SERVICE | 官方维修白名单（签名凭证） | 豁免物理开盖/短接，**不豁免** L3 核心区导出 |

**软件熔断 / 硬件熔断分开命名与验收**（评估报告 §4.3 建议 2）：
- **软件熔断** = 删全部分区 + `BRICKED` 标记 + 引导级拦截 → 系统不可恢复，**刷机可重装**（不叫永久变砖）。
- **硬件熔断** = 真机 eFuse/OTP 烧写或 crowbar 烧毁存储供电 → 物理永久变砖；**云端仅仿真指令锁存**，S6 才有。

### 4.3 其它招牌能力
输错即自毁保险库 ✅｜离线可验销毁证明 ✅｜胁迫口令/诱饵环境 ✅｜一键熔断 Panic ✅｜
设备自证 Attestation ✅｜TEE 密钥锚点（软件当前/硬件真机）✅｜防篡改审计链 HMAC ✅｜
首启 OOBE 强设零存储专用密码（20–30 位/大小写+特殊/连续序列≤5/10 秒冷却/不可找回）✅｜
隐私指示器+权限时间轴（构思）｜防肩窥/认证防录屏（构思）｜验证启动链 H1（未开始）。

## 7. 诚实边界（不实称完成）

1. **完整 Linux 手机 OS 目前远未达成**。仓库内 `secure/` 是本机 CLI、`kernel/` 是 R&D，
   **没有入仓的 Linux Image / rootfs qcow2 / 完整开机链路 / 桌面 / 软键盘**——这些是 S3 之前的真实差距。
2. `secure/` 标「已实现」的能力是 **x86_64 本机 CLI 程序**，**不是随 Linux 手机 OS 启动的服务**，离随系统出货有集成工作。
3. 物理检测（USB/开盖/短接/烧毁硬件）在云电脑是**故障注入仿真 / 仿真指令锁存**，不是真电气检测/真烧 eFuse；
   「任何方式破解不了」要真机 TEE/安全芯片/eFuse（S6）才成立。
4. 验证启动、故障隔离、地址隔离、内核硬化（H1–H4）属 Linux 内核与引导层，**未开始**。
5. 纯软件模拟、无 GUI 桌面长稳取证、无真机 TEE、安卓兼容层未接入，一律如实标注。
6. 熔断删系统 = 软件熔断（刷机可重装）；硬件永久变砖 = 真机 S6，二者不混用「永久变砖」措辞。
