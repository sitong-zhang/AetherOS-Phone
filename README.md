# AetherOS

AetherOS 是一套**基于 Linux 内核的移动操作系统（手机 OS），主打安全**。内核为 **Linux**
（v2 总文件产品目标为「Linux 内核 + 自研用户态」），用户态完全自研；不基于 AOSP、不基于现成
发行版。**目标是刷入开发板与谷歌 Pixel 真机实测**；当前在云电脑上做系统构建与调试，软件模拟
只是开发手段。**不做 APK、不套壳、不交付预览包**——系统本体就是真 OS（见 [`AGENTS.md`](AGENTS.md)）。

> ⚠️ **内核形态更正（2026-11-14）**：此前若干 commit 把落地层改成「自研 x86_64 内核（非 Linux 复用）」，
> 这与 V2 总文件、AGENTS.md 的「Linux 内核 + 自研用户态」直接矛盾，现纠正。**仓库内 `kernel/`
> 目录是一段研究性 R&D 代码**（从零学操作系统：引导 / 4 级分页 / 驱动 / 系统调用 / ring3），
> **并非产品内核**；其 ring3「安全 demo」经审计存在 V1–V17 多项缺陷（用户态可任意读写内核内存、
> 坏指针即整机停机、任务间无地址隔离等），**不代表产品安全能力**，详见 `AetherOS-漏洞清单-1114.md`
> 与 [`docs/KERNEL.md`](docs/KERNEL.md)。产品安全能力以 [`secure/`](secure/)（用户态安全整机本体，
> 179/0 自测，含 TEE 密钥锚点 / 设备自证 / 密钥绑定审计链 / 安全锁定熔断模式）及随 Linux 内核运行的安全子系统为准。

本项目的运行环境是**云电脑**，用软件模拟把整机真实跑起来：真实开机、真实出图、真实响应
输入。系统本体**不是 Android 应用、不是 APK、不是虚拟机套壳预览包**。

系统**主打安全**。产品安全能力由**用户态安全整机本体**（`secure/`，随 Linux 手机 OS 运行，
独立编译真运行）承载，已落地并真测试通过：
- **认证 / 加密保险库 / 自毁引擎**：口令连续错误达阈值即 **抹除全部用户数据**（销毁密钥 +
  多轮覆写 + 清除凭据），而**系统本体逐字节保留**；另有胁迫口令、防重启绕过计数、全盘静态加密、
  防篡改审计链、篡改即擦、紧急销毁、可离线校验的销毁证明。
- **TEE 锚点（密钥驻留）**：设备主密钥由安全锚点提供——当前软件后端（随机密钥落 `sys/device.key`，
  是硬件隔离的软件近似），真机阶段切换为 Pixel Titan M / eFuse 硬件后端（密钥驻留安全区、不可导出）。
  所有敏感密钥按域派生，互不通用。
- **设备自证（attestation）**：用设备密钥对当前安全状态做 HMAC 签名，产出可验证 JSON 报告，
  外部持有设备密钥即可核对完整性（对标 Android Key Attestation 的可验证报告）。
- **密码学基座**：SHA-256 / HMAC / PBKDF2(100k/200k 轮) / ChaCha20 / encrypt-then-MAC，
  全部自实现并经 OpenSSL 命令行交叉验证 4/4 一致。
- **安全锁定 / 熔断模式（招牌）**：首启 OOBE 强制设定一个 20–30 位、含大小写+特殊符号、
  连续序列≤5 的**专用安全密码**（二次确认弹窗明文回显 + 确定按钮 10 秒冷却）；
  系统**零存储密码明文**（只留不可倒推的验证锚），不可重置/不可找回、仅首次有效。
  `电源+音量下` 同按满 10 秒再点 `音量上` 进入安全锁定模式——此后**仅该密码可解锁**，
  其余路径全封死；**USB 强插 / 拆机 / 短接 → 报警 + 连系统一并抹除 + 永久变砖**。
  物理检测走 `aether_hal` 可替换接口（云端故障注入仿真，真机接 GPIO/TEE）。
  规格与验收见 [`docs/SECURITY-BASELINE.md`](docs/SECURITY-BASELINE.md)。

> 真实产品安全的"反例"与边界：`kernel/secure/`（自研内核侧）与 `kernel/` 整体属**研究性 R&D**，
> 经审计有 V1–V17 多项缺陷（用户态可越权读写内核、坏指针即停机、任务间无隔离），**不代表产品安全**，
> 切勿把其"安全 demo"当产品能力吹。

设计与验收见 [`docs/SECURITY.md`](docs/SECURITY.md)；R&D 内核侧见 [`docs/04-KERNEL-REPORT.md`](docs/04-KERNEL-REPORT.md)。

## 交付形态与双轨

一套上层源码，两条验证轨道，证据分开记录、互不顶替（见 `docs/ARCHITECTURE.md`）：

| 轨道 | 载体 | 只证明 | 不证明 |
| --- | --- | --- | --- |
| **A 轨 · 自研内核 R&D（研究性）** | QEMU x86_64 + TCG 纯软件模拟，从零学习用**自研 x86_64 内核**（非产品内核） | 仅证明「能从零写出一个能开机/分页/驱动/syscall/ring3 的内核」，是 R&D 练习 | **不代表产品安全**：经审计 V1–V17 多项缺陷，用户态可越权读写内核、坏指针即停机、任务间无隔离 |
| **B 轨 · 交互与像素**（设计目标，待重做取证） | 同一份上层源码 x86_64 原生构建，接口层接仿真实现 | 交互延迟、动画帧率、布局、对比度/遮挡/裁切、状态机、长稳 | 内核启动、真实驱动 |

> A 轨早期设计口径为「ARM64 + 自建 Linux 内核」；仓库内 `kernel/` 是一段从零学习用的**自研 x86_64 内核**
> （R&D，非产品内核），其 ring3「安全 demo」存在审计清单 V1–V17 多项缺陷，**不代表产品安全能力**。
> 产品的真实内核为 Linux（见 AGENTS.md / V2 总文件）。云电脑无 `/dev/kvm`，整机只能用 TCG 软件模拟。

**兼容层**：AetherOS 主系统完全自研；对既有应用格式的兼容能力由系统内一个独立子系统提供，
按容器化方式运行（可基于 AOSP / LineageOS / Waydroid 等开源实现）。兼容层内部运行的是
第三方应用，这与「系统本体是 APK」是两件不同的事。

## 快速开始

```bash
# 采集环境基线（v2 §2.1 要求动手前先跑一次）
python3 tools/collect_baseline.py

# 六种一键，统一入口（详见 docs/ARCHITECTURE.md 与 scripts/）
scripts/aether.sh build       # 从源码构建
scripts/aether.sh start       # 拉起整机（A 轨）/ 原生上层（B 轨）
scripts/aether.sh stop        # 正常关闭，清理进程/挂载/锁文件
scripts/aether.sh rebuild     # 清干净重来
scripts/aether.sh test        # 全套自测 + 五门机检，输出通过/失败清单
scripts/aether.sh evidence    # 截帧、导出状态与日志

# 安全整机：一键编译 + 81 项自测 + OpenSSL 交叉验证 + 整机演示 + 导出证据（含界面图）
scripts/secure.sh all
scripts/secure.sh shell       # 进入交互式整机 shell（init/unlock/put/panic/audit...）

# 自研内核：编译 + QEMU TCG 真启动 + ring3 安全 demo 闭环 + 真实帧缓冲取证 + 断言
scripts/kernel.sh build       # 编译内核（freestanding -Werror）+ ring3 init + initrd + 虚拟盘
scripts/kernel.sh test        # QEMU TCG 真启动，自动交互测试 + 真实帧缓冲取证 + 34 项断言
scripts/kernel.sh gate        # 内核门禁六门机检（构建/密码学/隔离/参数单一源/可复现/Multiboot）
```

不需要真实手机、真实外设或某家云厂商的私有接口；换一台云电脑也要能跑。

## 工程约定

- **参数单一源**：所有尺寸、间距、时长、圆角、阈值集中在 `guest/src/aether-tokens.h`；
  业务代码不许出现裸数值，由机检脚本扫描。
- **硬件访问只在 L2 及以下**：L3 以上源码不许出现 `/dev/`、`/sys/class/`、`/proc/` 直连，
  由机检脚本判定。
- **不自改门禁**：验收标准、门禁脚本、断言阈值不由执行方修改；每次改动留 diff 与回滚点。
- **外部资产**：素材自带优先；必须外取的提供校验和与许可声明，缺失时显式报错而非静默降级。
