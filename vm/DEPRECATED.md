# 已归档停用：APK 套壳工程

> 本目录（`vm/`）是**历史交付形态**的源码存档，保留用于追溯，不再是 AetherOS 的交付形态，
> 不参与当前构建、启动、测试与验收。请勿据此目录理解当前系统。

## 停用原因

当前唯一需求源《AetherOS 需求总文件 v2》§1.3 / §13 明确规定：

- 交付物是在云电脑上用软件模拟**真实运行的整机系统 + 自动化测试 + 逐阶段证据**；
- **不做 APK、不做虚拟机套壳、不做「装个 App 看效果」的预览包**；
- 内核与根文件系统必须从源码构建，或提供带校验和的获取脚本；禁止机器绝对路径。

本目录内容（`AndroidManifest.xml`、Java/JNI 层、`build_apk.sh`、`make_system_v*.sh`、
QEMU 参数组装等）服务于「自包含 Android APK 内嵌 QEMU」这一旧形态，与上述口径冲突，
因此归档停用。

## 保留范围与边界

## 仍可复用的内容

历史验证中积累的、与交付形态无关的工程结论仍有效，但**不作为 v2 验收证据**：

- ext4 系统盘注入前须 `e2fsck -fy` 回放并清空 journal，否则大文件数据块会被回滚；
- fbdev 帧缓冲不能假设 32bpp，需按 `fb_bitfield` 真实位域打包像素；
- TCG 软件模拟下合成器需避免全屏高成本模糊导致看门狗误判；
- 矢量字体以 `objcopy` 静态链入，规避向 ext4 注入大文件的一致性风险。

这些结论在 S1 自建根文件系统与 A 轨取证时会重新引用并**按 v2 口径重新取证**。

## 兼容层说明（避免混淆）

「系统本体不做 APK」与「兼容层能运行第三方 Android 应用」并不矛盾：兼容层是系统内一个
独立子系统，以容器化方式提供既有应用格式的运行环境（可基于 AOSP / LineageOS / Waydroid
等开源实现），其内部运行的第三方应用可以是 APK 格式。本目录的 APK 套壳工程属于**把系统
本体装进 APK**，与兼容层是两件不同的事，不在复用范围内。
